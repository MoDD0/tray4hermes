KDE/Plasma tray monitor a ovladač pro **Hermes Gateway**, messaging službu,
která je součástí
[Hermes Agenta](https://github.com/NousResearch/hermes-agent) od Nous Research.

> tray4hermes je vůči **Hermes Agentovi read-only**. Ovládá gateway přes
> `systemctl --user`, ukládá jeden vlastní malý JSON a všechno ostatní
> jen čte. Neukládá tokeny, nekonfiguruje providery, needituje
> `~/.hermes/config.yaml`. To všechno je doména samotného Hermes Agenta.

---

## Přehled

`hermes-gateway` běží jako služba pod `systemd --user`. tray4hermes k ní
přidává KDE tray rozhraní pro monitoring a ovládání. Aplikace:

- **ukazuje stav gateway** přímo v KDE panelu (zelená/oranžová/červená)
- **umožňuje Start / Stop / Restart** bez otevírání terminálu
- **přepíná profily** (`default`, `work`, `off`…) z menu
- **zobrazuje logy** ve vieweru s barevnými úrovněmi, filtry per úroveň,
  hledáním, rozpoznáváním tracebacků a časovým oknem
- **umí anglicky i česky**, přepnutí za běhu bez restartu
- **čte runtime stav Hermesu** a používá standardní `systemctl` API.

> ⚠️ **Disclaimer:** tray4hermes je *pasivní doplněk pro pohodlí*, ne
> oficiální komponenta Hermes Agenta. Hermes Agent funguje naprosto
> v pořádku i bez něj. Používej ho, pokud ti dává smysl; ignoruj ho,
> pokud ne.

## Funkce

- 📊 **Živá stavová ikona** v systémové liště (🟢 active, 🟠 warming,
  🔵 activating, ⚫ inactive, 🔴 failed, ⚪ unknown)
- ▶️ **Start / Stop / Restart** služby `hermes-gateway.service` jedním
  kliknutím
- 🔄 **Přepínač profilů** v submenu, řízený obsahem `~/.hermes/profiles/`
- 📋 **Prohlížeč logu** — *viz níže*, je docela vyladěný
- ⚙️ **Otevření konfigurace Hermesu** ve výchozím editoru
- 💻 **Spuštění Hermes CLI** v novém terminálu
- 🛠️ **Dialog nastavení** — jazyk UI a výchozí hodnoty, se kterými
  startuje prohlížeč logu; ukládá se vedle zbytku stavu trayky
- 🌍 **Anglické i české UI** — jazyk se vybírá v dialogu nastavení a tray
  se přepopisuje okamžitě, bez restartu; `tray4hermes -L cs` (nebo `en`)
  přebije uloženou volbu pro jeden běh a `tray4hermes --language`
  vypíše, co nainstalovaný build umí

### Prohlížeč logu

Prohlížeč čte `~/.hermes/logs/gateway.log` a nabízí:

- **Barevné úrovně logu**: `DEBUG` šedá, `INFO` bílá, `WARNING` žlutá,
  `ERROR` červená, `CRITICAL` červená + zvýraznění celého řádku
- **Sloupec s čísly řádků** jako v Qt Creatoru / VS Code
- **Filtry per úroveň** (přepínače na toolbaru) — vidíš jen to, co chceš
- **Přepínač TRACEBACK** — samostatná kategorie pro stack trace; vypni ji
  a uvidíš jen zprávy, zapni ji a máš obojí
- **Filtr časového okna** (Vše / 5m / 15m / 1h / 6h / 24h) — zobrazí jen
  logy z poslední hodiny apod.
- **Obrácené pořadí** — přepne na `journalctl` styl (nejnovější nahoře);
  každý nový záznam se objeví jako první
- **Spinbox Max řádků** — rolující buffer (0 = neomezeno). Krok 1;
  libovolnou hodnotu lze napsat ručně
- **Hledání** (`Ctrl+F` → `F3` další, `Shift+F3` předchozí, `Esc` zavřít)
- **Přepínač auto-scrollu** (výchozí ZAP; VYP = zachovat pozici při
  refreshi). Při zkoumání logu si viewer ručně vybranou pozici udrží
  i se zapnutým auto-scrollem; živý okraj sleduje jen tehdy, když na
  něm už jsi
- **Přepínač zalamování řádků**
- **Akce Kopírovat / Vyčistit / Obnovit**
- **Dialog nastavení** (velikost písma, max řádků, viditelnost úrovní, …)
- **Pamatuje si velikost a pozici okna** mezi otevřeními
- **Perzistence** — všechna nastavení se ukládají do
  `~/.config/tray4hermes/state.json`

## Architektura

```
┌──────────────────────────────────────────────────────┐
│  Hermes Agent (Nous Research)                        │
│  • hermes-gateway.service   (systemd --user)         │
│  • Hermes Desktop           (Electron consumer)      │
│  • CLI / TUI / MCP / Plugins                         │
└──────────────────────┬───────────────────────────────┘
                       │ sdílí
                       ▼
              ~/.hermes/    ←  jediný zdroj pravdy
              ├── config.yaml
              ├── auth.json
              ├── gateway_state.json
              ├── logs/gateway.log
              └── profiles/<name>/
                       ▲
                       │ čte (read-only)
┌──────────────────────┴───────────────────────────────┐
│  tray4hermes  (tenhle balíček)                       │
│  • ikona v liště  • Start/Stop/Restart               │
│  • přepínač profilů  • prohlížeč logu                │
│  • zapisuje jen: ~/.config/tray4hermes/state.json    │
└──────────────────────────────────────────────────────┘
```

Balíček nemá žádnou vazbu na zdrojový kód Hermes Agenta. Zná jen soubory
v `~/.hermes/`, název systemd unity a cestu k `hermes` CLI. Tray jde
kdykoliv odinstalovat, aniž by to gateway ovlivnilo.

## Stavový model

Tray skládá dva zdroje pravdy do šesti diskrétních stavů:

| Kód | Ikona | Význam |
|------|------|---------|
| `active` | 🟢 | Gateway běží, alespoň jedna platforma připojená |
| `warming` | 🟠 | Gateway běží, credentials/platformy se inicializují |
| `activating` | 🔵 | systemd službu startuje |
| `inactive` | ⚫ | Gateway zastavená |
| `failed` | 🔴 | systemd unit selhala |
| `unknown` | ⚪ | Stav nelze určit (oba zdroje nedostupné) |

`gateway_state.json` je primární zdroj, dokud je čerstvý (< 1 hodina);
`systemctl is-active` je fallback. Dvouzdrojový návrh obchází OAuth
warm-up závod, kdy systemd unit hlásí `active` ještě pár sekund před tím,
než první volání modelu skutečně projde.

## Podpora platforem

**Primárně vyvíjeno a testováno na Manjaro KDE** (rolling release,
Plasma 5, `xcb` X11 backend).

**Nativně by to mělo fungovat na každém Linuxu, který má:**

1. **Qt5 + PyQt5 nebo PySide2** (`python -c "from PyQt5.QtWidgets import QSystemTrayIcon; print('OK')"`
   musí projít)
2. **DBus session bus** (`echo $DBUS_SESSION_BUS_ADDRESS` má být
   nastavený — v desktop session typicky automaticky)
3. **Implementaci systémové lišty** respektující freedesktop.org SNI spec
   (KDE Plasma, Xfce, LXQt, Cinnamon, MATE, GNOME s rozšířením,
   Elementary OS s rozšířením…)
4. **systemd --user** (nebo něco kompatibilního — alternativy OpenRC /
   runit mají trochu jiné `hermes-gateway` API; bylo by potřeba
   dopsat adaptér v `paths.py`)

### Ubuntu s Unity / GNOME / jinými

Tohle je **tray aplikace**, takže hlavní rozdíl je v podpoře lišty:

- **Ubuntu + KDE Plasma** (`apt install kubuntu-desktop`) — mělo by
  fungovat rovnou, možná budeš muset doinstalovat `python3-pyqt5` přes
  `apt` nebo si dát `pip install PyQt5`.
- **Ubuntu + Unity (22.04+)** — Unity má vlastní indicator tray, ne SNI.
  Musely by se upravit `icons.py` a `app.py` tak, aby se registrovaly
  přes DBus na `com.canonical.Unity.LauncherEntry`. Technicky možné, ale
  dnes to není implementované. Pokud běžíš na Unity a chceš to — otevři
  issue.
- **Ubuntu + GNOME 41+** — GNOME záměrně **nepodporuje tray** bez SNI
  rozšíření. Musíš doinstalovat rozšíření jako
  [AppIndicator Support](https://extensions.gnome.org/extension/615/appindicator-support/),
  pak by to mělo fungovat.
- **Ubuntu + Cinnamon / MATE / XFCE** — všechny SNI tray podporují, mělo
  by to fungovat rovnou.

### Praktické doporučení pro uživatele Ubuntu

Krátká verze: **nainstaluj si KDE Plasma** a bude to fungovat
s nejvyšší pravděpodobností. Není to nejmenší balíček, ale je to
nejčistší cesta.

```bash
# 1. Nainstaluj KDE Plasma desktop (meta-balíček, ~600 MB)
sudo apt install kde-plasma-desktop

# 2. Odhlas se. Na přihlašovací obrazovce vyber session "Plasma" a přihlas se.

# 3. V terminálu uvnitř KDE session:
sudo apt install python3-pyqt5    # systémový PyQt5
python3 -m pip install --user tray4hermes  # nebo z GitHubu
python3 -m tray4hermes             # spusť tray

# 4. Pro autostart po přihlášení:
# Soubor .desktop je součástí nainstalovaného wheelu:
#   /usr/local/lib/python3.*/site-packages/tray4hermes/data/tray4hermes.desktop
# (cestu zjistíš přes `python3 -c "import tray4hermes; import os; \
#   print(os.path.join(os.path.dirname(tray4hermes.__file__), 'data', 'tray4hermes.desktop'))"`)
# Zkopíruj ho do ~/.config/autostart/ a uprav řádek Exec= tak, aby mířil
# na tvou instalaci tray4hermes.
```

**Proč to doporučujeme:**

1. **Hermes Agent** běží na Ubuntu úplně stejně jako na Manjaru (obojí je
   Linux, obojí má systemd --user, obojí má Python 3.11+). S Ubuntu
   *žádná* inherentní nekompatibilita není.
2. **Lišta v KDE Plasma** implementuje SNI spec nejdůkladněji ze všech
   DE — žádný workaround, žádné rozšíření, žádné „možná funguje".
3. **Vyšší šance na úspěch napoprvé.** Místo 75–95 % u GNOME / Cinnamonu
   s workaroundem dostaneš ~99 %.

**Alternativa pro puristy:** pokud na GNOME trváš a opravdu to chceš
rozjet tam, postupuj podle sekce `Ubuntu + GNOME 41+` výše. Není to ale
triviální první zkušenost.

### Budoucí testování

**Vlastní Ubuntu VM**: kdyby komunita přinesla reálnou poptávku po
podpoře Ubuntu, rádi bychom postavili jednoduchou **Ubuntu LTS VM**
(VirtualBox nebo LXC) s KDE Plasma v CI a pustili smoke test —
`tray4hermes` nastartuje → ikona v menu se objeví → klik na Start/Stop →
ověření, že `systemctl --user` reaguje. Stálo by to ~1–2 dny setupu +
skripty. Teď to nemáme, protože poptávka je **nulová** (Manjaro/KDE
pokrývá ~95 % uživatelů, kteří nám psali). Pokud bys to chtěl, přidej to
do Roadmapy. Otevři issue s `+1` a hlasem, nebo se prostě ozvi. 🙂

### Troubleshooting

Když se tray na jiné distribuci **vůbec neukáže**:

```bash
# 1. Ověř, že Qt5 vidí systémovou lištu
python -c "from PyQt5.QtWidgets import QSystemTrayIcon, QApplication; \
           app = QApplication([]); print('available:', QSystemTrayIcon.isSystemTrayAvailable())"

# 2. Zkontroluj, jestli běží DBus
echo "DBus session bus: $DBUS_SESSION_BUS_ADDRESS"
dbus-launch --autolaunch=output-file=/tmp/dbus.out

# 3. Zkus explicitní XDG
export XDG_CURRENT_DESKTOP=KDE
export XDG_SESSION_TYPE=x11
tray4hermes --debug
```

Pokud `QSystemTrayIcon.isSystemTrayAvailable()` vrátí `False`, je to
**problém kombinace distro/desktop**, ne bug tray4hermes. Můžeš:
- otevřít issue s výstupem `python -c "import sys; print(sys.platform, …)"`
  a s verzí Qt (`PyQt5.QtCore.PYQT_VERSION_STR`)
- zeptat se v komunitě Hermesu (nebo rovnou u nás v issues, pomůžeme
  rozšířit `paths.py` na tvůj setup)

Chceme, aby to fungovalo **všude**, kde má Hermes Agent šanci běžet.
Distrospecifické PR jsou proto velmi vítané.

## Instalace

### Koncový uživatel (systémově)

```bash
uv pip install --system tray4hermes
# nebo přes pipx:
pipx install tray4hermes
```

Pak povol autostart:

```bash
# Najdi, kam se .desktop soubor po instalaci dostal
DESKTOP_FILE=$(python3 -c "import tray4hermes, os; \
  print(os.path.join(os.path.dirname(tray4hermes.__file__), 'data', 'tray4hermes.desktop'))")
cp "$DESKTOP_FILE" ~/.config/autostart/tray4hermes.desktop
# Uprav řádek Exec= tak, aby mířil na nainstalovaný skript tray4hermes
# (wheel ho instaluje do <prefix>/bin/tray4hermes).
```

### Vývoj (editable)

```bash
git clone https://github.com/MoDD0/tray4hermes.git
cd tray4hermes
uv pip install --system -e ".[dev]"
./scripts/dev.sh   # nainstaluje závislosti + spustí testy
```

Spuštění trayky:

```bash
# Buď přes nainstalovaný konzolový skript:
tray4hermes

# Nebo přes watchdog wrapper (restart po pádu):
./run.sh

# Nebo jako modul:
python -m tray4hermes
```

## Bezpečnost

Tenhle balíček **nepracuje s žádnými credentials, tokeny ani secrets**.
Jediný soubor, který zapisuje, je `~/.config/tray4hermes/state.json`,
a obsahuje název aktuálně vybraného profilu, předvolby prohlížeče logu
a verzi schématu:

```json
{
  "version": 1,
  "selected_profile": "default",
  "log_settings": {
    "max_lines": 2000,
    "auto_scroll": true,
    "word_wrap": false,
    "font_size": 9,
    "show_levels": ["ERROR", "WARNING", "INFO", "DEBUG", "CRITICAL", "TRACE"],
    "show_tracebacks": true,
    "time_window_minutes": 0,
    "reverse_order": false
  }
}
```

Pokud najdeš bezpečnostní problém, otevři prosím **neveřejné** hlášení
přes funkci „Report a vulnerability" na GitHubu (Settings → Security →
Report a vulnerability). Zranitelnosti **nezveřejňuj** ve veřejných
issues ani commitech.

### Model hrozeb

| Vektor | Ochrana |
|--------|------------|
| RCE přes podvržený `gateway_state.json` | Načítá se jen jako JSON; žádný `eval`/`exec`/shell. Striktní tvar dat. |
| Injektáž do logu | Prohlížeč logu je read-only; používá `QPlainTextEdit` (escapuje HTML). |
| Injektáž cesty přes profil | Název profilu validuje sám Hermes Agent (`hermes profile use` vrátí nenulový kód, pokud profil neexistuje). |
| Závod nad lock souborem | `O_CREAT\|O_EXCL` + kontrola živosti PID + jedno rekurzivní opakování. |
| Vyčerpání místa při zápisu `state.json` | Atomický `tmp` + `os.replace`; adresář se zakládá s `parents=True`. |

Tray je vůči zbytku Hermes Agenta odstíněný: ani zero-day v tray4hermes
nepřečte `auth.json` ani `.env` a nespustí volání modelu. Nejhorší, co
umí, je spadnout a nechat se restartovat watchdogem — načež jen přečte
(pořád nedotčený) stav a překreslí ikonu.

## Přispívání

Issues, komentáře, návrhy — všechno vítáno. Ať už je to:

- 🐛 **Bug report** — ideálně s výstupem z `~/.hermes/logs/gateway.log`
  a z `tray4hermes --debug`
- 💡 **Feature request** — krátký popis, k čemu by to bylo. Nevadí nám
  ani „divoké" nápady (jiný backend, podpora Waylandu, vlastní ikony…).
  Stojí to za diskuzi.
- 🎨 **Úprava UI** — barvy, layout, fonty, tooltipy. Tohle je oblast,

- 📖 **Dokumentace** — chybí screenshoty prohlížeče logu, klidně je

- 🌍 **Lokalizace** — UI jde přes `gettext` a dodává se anglicky a

  `src/tray4hermes/_locales/`; překlady README žijí zvlášť
  v `docs/i18n/`. Obě cesty popisuje
  [CONTRIBUTING.md](../CONTRIBUTING.md)
- 🐧 **Distrospecifické opravy** — viz
  [Podpora platforem](#podpora-platforem). Každá distribuce, na které
  testujeme, je jeden PR daleko

### Jak poslat PR / patch

```bash
git clone https://github.com/MoDD0/tray4hermes.git
cd tray4hermes
./scripts/dev.sh            # nainstaluje závislosti, spustí testy
# proveď svou změnu
./scripts/dev.sh -v         # znovu testy, tentokrát verbose
uv run ruff check src tests
uv run ruff format src tests
git commit -m "popis"
git push
```

Pravidla (pružná):

1. **Nerozbíjej testy.** Celá sada musí zůstat zelená —
   `./scripts/dev.sh` ji spustí.
2. **Nepřidávej nové runtime závislosti** bez diskuze — balíček má
   jedinou runtime závislost (`PyQt5`) a chceme to tak udržet.
3. **Žádné secrets v diffu**
   (`grep -rE "sk-[a-z0-9]{16,}|api_key.*[a-z0-9]{20,}"`).
4. **Žádné zápisy do `~/.hermes/*`** zevnitř trayky — tuhle oblast
   vlastní Hermes Agent.
5. **Příspěvky kompatibilní s MIT.** Pokud přidáváš kód, drž se MIT
   licence.

Pokud se ti projekt líbí a máš nápad, **prostě otevři issue** — probereme
to. I „tohle slovo v překladu nezní dobře" je vítaná zpětná vazba.

## Roadmapa (nápady na příště)

Pár věcí, které mi leží v hlavě a hotové zatím nejsou. Pokud tě něco
z toho zajímá víc než zbytek, ozvi se:

- **Podpora Waylandu** — dnes jen `xcb` (X11) kvůli tray API v KDE
  Plasma; Plasma 6 + Qt6 by Wayland otevřely. PR vítány.

- **Hledání v logu napříč sessions** (FTS5 nad databází sessions)
- **Notifikace při ERROR** — toast přes D-Bus, když gateway zapíše
  traceback (mně se to líbí, ale je to věc vkusu)
- **Export/import nastavení** — sdílení presetů prohlížeče logu mezi
  profily
- **Ubuntu LTS VM v CI** — viz
  [Podpora platforem → Budoucí testování](#budoucí-testování)
- **Port na Plasma 6 / Qt6** — pro den, kdy Manjaro začne dodávat
  Plasma 6 jako výchozí
